# 去中心化安全社交网络

基于 Hyperswarm 的 P2P 端到端加密即时通讯系统

## 🎯 项目简介

这是一个完整可运行的去中心化安全社交网络系统，展示了现代 P2P 网络和端到端加密技术的实际应用。

### ✨ 核心特性

- ✅ **完全去中心化** - 无需中央服务器，P2P 直接通信
- ✅ **自动节点发现** - 基于 DHT 的分布式节点发现
- ✅ **端到端加密** - NaCl 加密库，第三方无法窃听
- ✅ **多设备检测** - 智能检测并防止账号被盗用
- ✅ **用户友好** - 统一客户端，交互式登录
- ✅ **邀请码系统** - 一键创建和加入聊天群组

## 🚀 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 启动客户端

**打开第一个终端（User1）：**
```bash
npm start
```
输入用户名和密码（例如：user1 / password123）

**打开第二个终端（User2）：**
```bash
npm start
```
输入用户名和密码（例如：user2 / password456）

### 3. 创建群组并聊天

**在 User1 窗口：**
```
/create 我的聊天室
```
复制显示的邀请码

**在 User2 窗口：**
```
/join <粘贴邀请码>
```

等待10秒连接建立后即可开始聊天！

2. 终端2：User2 加入群组

**终端3 启动 Eve：**
```bash

**输入邀请码**（直接粘贴User1的邀请码）：

```

**Eve 自动解析：**
```
📋 解析邀请码成功:
   群组ID: abc12345
   群组名称: 我的聊天室
   创建者: user1
```

**Eve 监听输出：**
```
🕵️  [消息 #1] 截获加密消息！
   发送者: user1
   时间: 2024-01-15 15:30:45
   加密内容: U2FsdGVkX1+vupppZksvRf5pq5g5XjFRIipRk...
   完整长度: 128 字符

🔓 尝试暴力破解...
   ✗ 密钥1 解密失败
   ✗ 密钥2 解密失败
   ✗ 密钥3 解密失败
   ✗ 密钥4 解密失败
   ✗ 密钥5 解密失败

❌ 破解失败！无法解密消息内容。
💡 这证明了端到端加密的安全性！

📊 窃听统计:
   截获消息: 1 条
   解密尝试: 5 次
   成功破解: 0 次 (0.0%)
   安全性: ✅ 加密有效！
```

**结论：** Eve 可以监听网络流量并截获所有加密消息，但由于没有正确的加密密钥，无法解密任何内容。这证明了端到端加密的安全性——只有拥有正确密钥的群组成员才能解密消息。

## 🔧 技术栈

### 网络层
- **Hyperswarm** - 现代 P2P 框架（2024年技术）
- **DHT** - 分布式哈希表，自动节点发现
- **NAT 穿透** - 自动处理防火墙，跨网络可用

### 加密层
- **Scrypt** - 密钥派生函数（KDF），从用户名+密码生成密钥
- **Ed25519** - 非对称加密，用于身份验证
- **XSalsa20-Poly1305** - 对称加密算法，消息加密
- **TweetNaCl** - 工业级加密库

### 安全特性
- **端到端加密** - 只有收发双方能解密消息
- **多设备检测** - 基于公钥验证，防止账号盗用
- **密码哈希存储** - SHA-256 哈希，不存储明文
- **会话管理** - 随机会话ID，区分不同设备

## 🔍 常见问题

### Q1: 为什么 `/users` 显示 0 个在线用户？

**A:** 需要等待5秒让 P2P 网络连接建立。步骤：
1. 确保两个用户都已登录成功
2. 等待5-10秒
3. 再次输入 `/users`

---

### Q2: 如何在两台电脑上演示？

**A:** 完全相同的步骤：
1. 在两台电脑上分别运行 `npm install`
2. 第一台：`npm start`，登录并创建群组
3. 第二台：`npm start`，登录并使用邀请码加入
4. 等待10-15秒让 DHT 发现节点

---

### Q3: 为什么连接数是 0？

**A:** 可能原因和解决方案：
1. **等待时间不够** - 等待10-15秒
2. **防火墙阻止** - 临时关闭防火墙测试
3. **其他用户未上线** - 确保对方已登录

---

### Q4: 多设备登录检测是如何工作的？

**A:** 系统通过公钥验证身份：

**相同密码（公钥相同）**：
- 新设备：显示"该账户已登录"，返回登录界面
- 老设备：收到"密码可能泄露"警告

**不同密码（公钥不同）**：
- 新设备：显示"该用户已存在"，返回登录界面
- 老设备：无提示（避免骚扰）
